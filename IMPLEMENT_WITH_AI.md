# One-shot implementation prompt

You are an implementation engineer working on this user's CachyOS + Niri laptop. First ask: “What should I call your assistant?” Offer Friday as one option, a custom name, or skip/disable the assistant. Never silently force Friday. Save the selected display name and optional wake phrase in one editable user setting; do not repeat the name question on later launches. Then ask which scope the user wants: all items or selected items from `docs/implementation-inventory.md`. If they say all, implement every supported feature below; keep unsupported items documented and safely disabled.

## Goal and full scope

Deliver a fast, secure, recoverable Mac-inspired CachyOS desktop while keeping Niri. Reconcile current reality from the live machine with the consolidated feature inventory and `docs/feature-spec.md`: Niri/Noctalia translucent 32px-class menu bar; sharp vector status icons, consistent typography/date/time; focused app title/menu only when a window is focused; working Control Center for Wi-Fi, Bluetooth, audio, battery, brightness, Focus and settings; real truthful NetworkManager/BlueZ/PipeWire state; outside-click/Escape dismissal; translucent auto-hiding/resizable dock; Alt+Space launcher with four useful categories; tested close/hide-restore/maximize top-bar controls; notifications; Win+L secure PAM-backed video lock with DP and first typed key preserved; Nautilus Space preview tap/hold; trackpad gestures; Win+Shift+5 screenshot/recording toolbar via portal; Android KDE Connect; and Friday-style voice/text assistant with Win+Shift+F, optional local wake phrase, English, continuous follow-up, auto VAD stop/reply, goodbye/Escape/outside/lock/privacy stop, local AI/offline commands and optional text-only web search. Friday command coverage should include installed apps such as WhatsApp and Brave, open URLs in a requested browser (e.g. YouTube in Brave), actual system volume/brightness, media, time/battery, lock, screenshots, window/workspace actions, notes, timers and safe search. Show text always; speak only to a verified selected external output, with a licensed female English voice as preference. The profile photo/wallpaper/video remain user-local.

## Required process

1. Inspect OS/session, exact compositor/shell/helper versions, configs, package sources, running user services, available RAM/disk, output devices, input metadata and hardware. Treat repository/chat as history, not proof of live state. Never print secrets, env, credentials from process args, private files, photos, recordings, biometric templates, saved SSIDs/IP/MAC/device names.
2. Read `docs/implementation-inventory.md`, `docs/feature-spec.md`, `docs/current-state.md`, `docs/architecture.md`, `docs/setup.md`, `docs/testing.md`, `docs/safety-and-rollback.md`, `docs/sources.md`. Recheck official upstream docs and current package/API compatibility; record date, exact versions, URLs and evidence.
3. Before mutation, show a short feature-by-feature plan and conflicts; make owner-only per-file backups with checksum manifest, preserve user edits, and provide dry-run/diff. Make changes in independent small slices. Prefer official signed CachyOS packages, documented APIs and user-level services. Do not install KDE or replace Niri. No opaque curl-pipe-shell, unreviewed AUR scripts, blanket root scripts, or arbitrary model-generated shell.
4. Keep assistant actions strictly allowlisted: recognized text/model output may only map to fixed typed action IDs; never `eval`, shell interpolate, or pass transcript to shell. If speech is unclear say “Sorry, could you repeat that?” Do not launch repeated app instances on races; resolve desktop files and focus an existing window. Require explicit confirmation for destructive, messaging, financial, shutdown/restart actions. Always honor lock/privacy mute. Keep audio local/in memory, delete temporary audio. Web search sends query text only with opt-in. Never speak on built-in speakers; do not scan output devices on every turn. Never commit secrets or private user assets.
5. Keep lock PAM-authorized and fail-closed with password fallback. Fingerprint USB `27c6:5e0a` had isolated capture failures and later experimental success reports; verify exact installed driver/PAM against current official support, assess risk and keep password fallback. Do not blindly enable/disable, install proprietary root DLL, or change PAM without exact reviewed diff, explicit user approval and tested recovery.
6. Validate each slice: syntax, service start/state, real interaction, regressions, privacy/security and rollback. Do not disrupt active network/audio/lock/login or close apps during tests without safe setup. Never call mockups, old chat claims or synthetic ASR benchmarks real implementation evidence.
7. Update inventory and current-state with what was inspected, actually tested, failed and remains unsupported. Commit clean changes; report exact files, evidence and rollbacks.

Aim for macOS visual language without claiming pixel identity or redistributing Apple assets. Native app titlebars/menus cannot be replaced universally under Wayland; use closest Niri-native behavior and clearly document toolkit limits. Do not stop after planning—perform all safe, authorized work and finish supported features. Pause only for a concrete security-sensitive decision, required authentication or genuinely destructive/unsupported choice.
